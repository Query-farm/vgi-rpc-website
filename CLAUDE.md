# CLAUDE.md — vgi-rpc-website

## Project overview

Documentation/marketing website for the vgi-rpc framework. Built with **Astro 7 + Tailwind CSS 4**, deployed to **Cloudflare Pages**.

Live site: https://vgi-rpc.query.farm

## Commands

```bash
npm run dev        # Generate diagrams + start dev server
npm run build      # Generate diagrams + production build → ./dist/
npm run preview    # Preview production build locally
npm run diagrams   # Generate D2 diagrams to SVG (requires `d2` CLI)
```

## Project structure

```
src/
  pages/           # Astro file-based routing (index, wire-protocol, benchmarks)
  components/      # Reusable .astro components (Hero, Nav, Footer, etc.)
  layouts/         # BaseLayout.astro — HTML wrapper, Open Graph, JSON-LD
  styles/          # global.css — Tailwind imports + Query.Farm Strata Sun theme tokens
  data/            # capabilities.json (generated by scripts/test-capabilities.py, do not hand-edit)
  diagrams/        # D2 diagram source files
public/            # Static assets (logos, generated diagram SVGs, llms.txt)
scripts/           # test-capabilities.py — CI script that probes language implementations
```

## Key conventions

- **Astro components**: frontmatter (TypeScript) between `---` fences, template below. Props use `interface Props`.
- **Styling**: Inline Tailwind classes. Dark mode via `dark:` prefix. Responsive mobile-first (`sm:`, `md:`, `lg:`).
- **Design system**: Query.Farm **Strata Sun**, ported from `~/Development/query-farm-astro` (its `DESIGN_BRIEF.md` is the authority). Tokens in `src/styles/global.css`: `soil-*` grounds/text (paper `soil-50`, ink `soil-900`), `sun-*` gold for identity and accents, `field-*` green for CTAs and interaction, `rock-*` dark grounds and code, `cream`/`cream-2` text on dark, `link*`, `cat-*` tints only where hue carries meaning.
- **Contrast law**: `sun-700` is the only gold that may carry text on a light ground; `sun-400` gold is never body text; code blocks always sit on `rock-900`; buttons darken on hover.
- **Fonts**: Petrona 600 (headings, via `font-display`), Noto Sans (body; figures and numeric columns use `.qf-figure` / `td[data-numeric]`), JetBrains Mono (code), from Google Fonts.
- **External links**: Always use `target="_blank" rel="noopener noreferrer"`.
- **Brand**: Use lowercase `vgi-rpc` in monospace when referring to the framework. The project is by Query.Farm (capital Q and F, dot kept); the legal name, for copyright lines only, is Query Farm LLC.

## Writing

Copy should read as deliberate, not autopilot (after https://robotsatemyhomework.substack.com/p/ai-writing-patterns). The patterns below are allowed when they do work; cut them when they don't.

- **Say each claim once.** "No IDL" and "same code on every transport" live in the What Is section; other sections add new facts instead of restating them.
- **Negations and "not X, but Y"** only when they correct something a reader actually assumes (fine in the spec: "404, not 405"). No "No X, no Y, no Z" runs.
- **Lists of three** only when the third item carries weight; never pad to three.
- **No stock phrases**: "That's it", "without the ceremony", "in minutes", "no drama", "True X". Replace with a specific, checkable fact.
- **Vary endings**: don't close every card or section with a short punchy fragment.
- **Em dashes** are fine; don't stack them sentence after sentence. Use periods, colons, or parentheses for variety.
- **Avoid cleft delays** ("What makes this X is…", "that is what lets…"): state the point directly.
- Claims about features must match the wire-protocol page or the SDK docs.

## Data flow

- `scripts/test-capabilities.py` probes language repos (Python, TypeScript, Go, Rust, Java, C#, C++) for transport/pattern/feature support.
- Output goes to `src/data/capabilities.json` — consumed by `CapabilityMatrix.astro`. Worker/server conformance and declared native-client capabilities are separate sections of each language entry.
- Refresh declared capabilities manually with `python3 scripts/test-capabilities.py --known-only`; reviewed SDK versions and source commits live in `scripts/capability-sources.json`, independently of benchmark pins.
- The deployment workflow does not probe or refresh capabilities.

## CI/CD

- **Deploy** (push to main + manual): Node 22, installs D2, runs `npm run build`, deploys via Wrangler.
- **Capability update**: manual source review and regeneration; no scheduled capability-update workflow is installed.

## Dependencies

Minimal: `astro`, `@astrojs/sitemap`, `tailwindcss`, `@tailwindcss/vite`. No runtime JS frameworks.
